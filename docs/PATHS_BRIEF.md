# Paths — unlocking the value (strategy brief)

## The problem, stated honestly

Today the app's output *looks like* blocks of time with some breathwork
and a few exercise suggestions. The intelligence (adaptation, evidence
base, goal direction) is real but invisible: nothing on screen says *why
this week is shaped this way for you*. And the interview minimises input
so hard that the app never learns enough to feel personal.

## The insight on friction

Friction is not uniformly bad. A short *global* onboarding gets people in;
a deeper *domain* intake — taken when the user reaches for that domain —
builds commitment (effort → ownership) and is exactly the moment they'll
happily answer more. This is the natural pre-paywall moment: finish the
intake, see YOUR program, then meet the gate. Rule of thumb:

> **Global interview: minimum viable. Domain paths: as deep as the value
> they unlock — and never one question deeper.**

Every intake question must visibly change the plan. If the planner
doesn't use an answer, the question is deleted.

## The model: Paths

A **Path** is a guided domain program, not a settings page:

1. **Promise** — one screen stating what this path produces.
2. **Intake** — 3–5 questions (plus optional personal numbers like age
   and weight where the maths uses them), each altering the output.
3. **The plan, explained** — the week's blocks WITH their why (from the
   evidence library), personal numbers (a protein target, an automation
   order, protected deep-work hours), and milestones.
4. **A hub** — one screen per path showing progress, the next session to
   run, and the reasoning. The hub is what makes a block "meaningful time
   allocation" instead of an icon of time.

First four paths (each explicitly demanded): **Training · Nutrition ·
Money · Work**. The behaviour system (urges, triggers, intentions,
breathwork interrupts) is effectively the fifth — the addiction path —
and gets its own deepening round (trigger-specific interventions,
recovery framing) next.

## Personal data policy

Age and weight are asked only inside Training/Nutrition intakes, marked
optional, with the reason shown inline ("weight sets your protein
target"). Used on-device for: protein anchor (~1.6–2.2 g/kg by goal),
conservative-loading notes at 45+. Never required, never judged, never
sent anywhere in demo mode.

## What "minimise input, maximise value" means mechanically

- One shared knowledge base feeds all paths — answering once tailors many
  surfaces (interview → paths → library → AI).
- Intakes reuse the goal wizard's question bank where domains overlap.
- Behavioural learning (moves/skips/completions) keeps reducing the need
  to ask: the app infers what it can and asks only what it can't.

## Success test

A user who finishes one path intake should be able to answer, from the
hub alone: *what am I doing this week, why those blocks, what number is
mine, and what's the next milestone?* If any of those needs explaining in
chat, the hub has failed.
